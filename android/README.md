# nkchat — minimal Android app for the Rust MLS chat core

A thin Kotlin app that loads `libnk_crypto_tool.so` (the Rust core) through the
UniFFI bindings and drives [`MobileChatClient`]: create an MLS group, show this
device's connection ticket, etc. The crypto/storage/networking all live in Rust
(hybrid PQC MLS + redb + iroh) — this module is only a driver/UI shell.

## Layout

```
android/
  settings.gradle.kts  build.gradle.kts  gradle.properties
  app/
    build.gradle.kts
    src/main/AndroidManifest.xml
    src/main/res/values/strings.xml
    src/main/java/com/example/nkchat/MainActivity.kt
    src/main/jniLibs/<abi>/libnk_crypto_tool.so   ← staged by ./stage.sh (gitignored)
    src/main/java/uniffi/nk_crypto_tool/*.kt        ← generated by ./stage.sh (gitignored)
  stage.sh
```

## Build

1. One-time Rust→Android toolchain (see `../docs/guides/BUILD_ANDROID.md`): `rustup target
   add aarch64-linux-android x86_64-linux-android`, `cargo install cargo-ndk`,
   and an Android NDK (export `ANDROID_NDK_HOME`).

2. Stage the native lib + bindings:
   ```sh
   ./stage.sh
   ```
   This builds `libnk_crypto_tool.so` for `arm64-v8a` (devices) and `x86_64`
   (emulator) and generates the Kotlin bindings into the app sources.

3. Build / run the APK (needs JDK 17 + Android SDK; easiest via Android Studio):
   ```sh
   ./gradlew assembleDebug      # or :app:installDebug onto a device/emulator
   ```
   (No Gradle wrapper jar is committed — run `gradle wrapper` once, or just open
   `android/` in Android Studio which provides Gradle.)

## What the app does

- **Create MLS group** — `MobileChatClient.open(filesDir, passphrase,
  displayName, disableRelay=false)` then `createGroup()` / `listGroups()`.
- **Show my ticket** — `localTicket()`, the iroh address to hand a peer.

Two-device chat (invite → send/receive) uses `exportKeyPackage` /
`inviteMember` / `sendWelcome` / `joinGroup` / `sendText` / `receiveNext`
(see `MobileChatClient` in `../src/ffi.rs`); wiring a two-pane UI for it is the
next step. The end-to-end peer-to-peer flow is already covered by the Rust test
`two_clients_invite_and_exchange_message`.

## Verified

`./stage.sh && gradle assembleDebug` (JDK 17, cmdline-tools + platforms;android-34
+ build-tools;34.0.0, Gradle 8.9, NDK r27c) produces a working
`app/build/outputs/apk/debug/app-debug.apk` (~51 MB debug, 2 ABIs). The APK
bundles `lib/{arm64-v8a,x86_64}/libnk_crypto_tool.so` (the Rust core) plus
`libjnidispatch.so` (JNA). Installing/running on a device or emulator is the
remaining manual step.

## Notes

- UniFFI's Kotlin runtime uses **JNA** (`net.java.dev.jna:jna:*@aar`) to load
  the `.so`; that dependency is already in `app/build.gradle.kts`.
- `INTERNET` permission is required (iroh). For a fully offline LAN test, open
  the client with `disableRelay = true`.
